# Frontier Build

Reconstruct the exact source checkpoint and current capability truth before editing. Respect repository-native instructions and existing ownership boundaries.

Compile meaningful work into typed work units. Mark side effects explicitly and give them an independent VERIFICATION path. Use test-first behavior changes and preserve builder/verifier separation.

Treat model or JEV recommendations as `DecisionProposal`s: role/backend/topology suggestions may improve allocation, but admitted authority must remain a subset of the parent envelope.

Collect evidence per acceptance criterion. Bind proof to exact repository head and, where artifact content matters, exact subject SHA-256/artifact version. Changed subjects make old proof stale even if the repository head stayed constant.

If an external capability is below required maturity, stop that path with an explicit blocker rather than implementing around imaginary infrastructure. Finish only when current evidence satisfies the current subject.
